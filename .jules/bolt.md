## 2024-05-18 - Optimize Prisma FindMany and Count operations using transactions
**Learning:** Found sequential independent read queries like `findMany` and `count` executed one after the other. In Prisma, fetching data alongside its count sequentially takes up multiple database round trips causing performance degradation due to network latency, particularly on data grids like the Content History dashboard or tables with heavy pagination. Using `prisma.$transaction` combines operations in a single network round-trip.
**Action:** Always inspect `.findMany()` queries with a sequential `.count()` query right below it. Batch these operations by passing both queries to an array `await prisma.$transaction([prisma.model.findMany({}), prisma.model.count({})])`. Ensure you extract shared `where` filters properly into a common constant to reduce error-prone query parameter duplication.
